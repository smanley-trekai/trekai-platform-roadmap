What successful coverage means

ControlChecks before we mark it verified
Runtime sensorThe supported sensor checks in with the intended policy.
A safe test produces the expected events for that exact target.
Image scanningThe registry connection works and scans the deployed image digest.
Findings reach an owner and follow the agreed release policy.
Security logs and alertsRepresentative events arrive, parse correctly and identify the target.
A test alert reaches the responsible person and backup contact.
Access and recoveryAllowed actions work, unauthorized actions fail,
temporary elevation ends and agreed recovery checks pass.

Recheck coverage after sensor updates, node replacement and integration changes.
A healthy application alone does not prove its security controls work.

Security in the QA environment template

  • Include scoped identities, network isolation and secret references
    in the approved QA template.
  • Enable applicable runtime protection, image scanning
    and required security logs when the environment starts.
  • Run the agreed security-readiness checks before handing QA the URL.
    A failed required check holds handoff unless an exception is approved.
  • Apply the agreed test-data, expiry and cleanup rules.
    End temporary access and retain required incident records.

DevOps owns the template and checks. QA uses the controlled request workflow.
