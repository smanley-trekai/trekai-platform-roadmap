Documentation: where it is today

LocationWhat is there
ConfluenceTrek-Learning (New) holds architecture and operating guides.

GitHubRepository READMEs and instructions sit beside the code.
Terraform and deployment details are spread across repositories.
2nd BrainCollected documentation, system explanations and review notes.
Use it to find context; check which guidance is approved and current.
Useful documentation already exists in several places.
The team needs a clear starting point and one primary guide for each task.

Documentation: what needs to improve

  • The Operations & Runbooks structure already exists,
    but reviewed content still needs to be moved or linked into it.
  • The Deployment & Release index still has no assigned owner.
  • Some guidance describes older workflows.
    Check instructions against the code and actual operating process.
  • Confirm which guides are missing, duplicated or hard to find
    before deciding what to rewrite.

What every operating guide should include

Part of the guideWhat the reader needs
Purpose and scopeThe task, product, environment and applicable version.
Access and preparationRequired permissions, inputs and checks before starting.
Use secret references instead of credential values.
Steps and outcomeClear steps, expected results and how to verify success.
Explain when to stop and how to recover or roll back.
Ownership and statusA named owner, reviewer, status and review date.
Record when the procedure was last successfully tested.

Keep proposed designs clearly separate from instructions approved for use.

How we keep documentation current

TriggerProposed maintenance rule
A system or access changeThe change owner updates affected guides and links.
The reviewer checks documentation before closing the work.
An incident or reader problemRecord the gap in a task, assign an owner and fix it.
Update the runbook with the tested resolution or workaround.
A scheduled reviewPropose monthly checks for critical runbooks
and quarterly checks for reference pages. Agree this with owners.
An obsolete or unowned pageMark its status clearly. Assign it, correct it or archive it.
Point old links to the replacement and escalate overdue work.

DevOps coordinates the index; each system owner is accountable for their guides.

Documentation: decisions for the team

  1. Can we use Confluence as the DevOps starting point,
    with code-specific instructions maintained in GitHub?
  2. Which tasks should we document first,
    and who owns and reviews each guide?
  3. Which guides must be ready before a release or handoff,
    and what review schedule can the team maintain?
  4. Who will trial the first QA guide
    and help resolve gaps or conflicting instructions?
