Our infrastructure and deployment code lives in separate repositories.

DevOps: proposed setup

One repository for the infrastructure, deployment and automation code
we agree to bring together.

Example folderWhat it contains
terraform/Infrastructure code, separated by product and environment.
gitops/Application deployment configuration for each product.
automation/Agreed scripts and Ansible code.
.github/ and docs/Shared checks, review rules and operating instructions.
Each environment keeps its own state, permissions and deployment rules.
Code that needs separate read access stays in a separate repository.

Hub/LMS: current setup

The Trek Learning application stack is split across service repositories.

AreaCurrent setup
Web and core APIsThe web interface, core service and authentication service
have separate repositories.
AI toolsAI, chat, tutor and grading services
have separate repositories.
Content and filesIngestion, retrieval, file handling and batch jobs
have separate repositories.

Application workflows build images and update GitOps configuration.
Argo CD uses that configuration to deploy the services.

Hub/LMS: proposed setup

One product repository for related application code and shared tooling.

Example folderWhat it contains
apps/The Hub/LMS web interface.
services/A separate folder for each backend service.
packages/Reusable code where sharing it is useful.
.github/ and docs/Shared checks, local setup and team instructions.
Services keep their own builds, images and releases.

Coordinate Terraform/GitOps with DevOps. Agree database and pipeline scope.

CAP/TrekFinder: current setup

TrekFinder is the application. CAP provides the adaptive engine.

AreaCurrent setup
TrekFinder appThe UI and backend are in separate repositories.
CAP engine and servicesEngine modules and supporting services
are spread across repositories.
Builds and testsCI policy, integration tests, application tests
and benchmarks have separate repositories.
Some engine source and CI policy have restricted access.
The repository structure must preserve those access rules.

CAP/TrekFinder: proposed setup

Bring related product code together while keeping restricted source controlled.

LocationWhat it contains
Product monorepoTrekFinder UI and backend, plus services, modules and tests
that can share the same source access.
Restricted repositoriesProtected engine source and trusted CI policy.
Authorized builds provide approved images or packages.
DevOps repositoryAgreed Terraform and GitOps code,
coordinated with the DevOps monorepo plan.
Group code by who is allowed to read it.
Folder review rules cannot protect restricted source inside a shared repository.
